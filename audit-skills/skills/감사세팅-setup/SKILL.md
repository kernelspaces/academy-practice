# 감사세팅

감사 스킬 묶음의 관리 스킬이다. 폴더를 만들고, 권한 파일과 훅을 적고, 현황 화면을 만든다. 감사 업무(요청자료 · 정산표 · 푸팅)는 다른 스킬이 한다.

이 스킬 폴더(아래 `<세팅>`)는 이 SKILL.md 가 있는 폴더다. 명령은 cd 하지 않고 절대 경로로 돌린다. 예: `python "<세팅>/bin/hub.py" setup --root "<감사 루트>"`.

## 플러그인과 다른 점

스킬만 설치한 배포본에는 플러그인 훅이 없다. 그래서 `설치` 와 `새회사` 가 같은 훅 넷을 폴더의 `.claude/settings.json` 에 적는다.

| 훅 | 하는 일 |
|---|---|
| SessionStart | 세션을 열 때 현황 한 줄(회사 · 결산일 · 요청 받음과 빠짐 · 받은자료 수 · 남은 일 수)을 대화 맨 앞에 넣는다 |
| UserPromptSubmit | 지시 앞 120자를 `_기록/기록.jsonl` 에 남긴다 |
| PostToolUse(Edit · Write · Skill · Bash) | 고친 파일, 부른 스킬, 스킬 스크립트를 돌린 명령을 기록한다. 4000 조서 설계 md 면 필수 절차 목록과 대조한 결과를 대화에 넣는다 |
| Stop | 토큰을 기록하고, 파일을 고치고 진행메모를 안 고쳤으면 알린다 |

- 훅은 그 폴더를 처음 열 때 폴더 신뢰를 승인해야 돈다.
- 훅 경로는 이 스킬 폴더의 절대 경로다. 스킬 폴더나 감사 루트를 옮겼으면 `설치` 를 다시 돌린다.
- 회계위키(기준서 · 질의회신 · 감리지적사례)는 `설치` 와 `새회사` 가 폴더의 `.mcp.json` 에 적는다. 세션을 처음 열 때 이 서버를 쓸지 묻는 승인을 누르고, `/mcp` 에서 accountingwiki 를 골라 로그인한다.

## 설치 (감사 루트 만들기 · 점검)

「이 폴더를 감사 루트로 만들어줘」, 「설치 점검」.

1. 말한 폴더가 있으면 그 폴더를, 없으면 지금 폴더 위쪽의 감사 루트를, 그것도 없으면 사용자 폴더 아래 `감사` 를 감사 루트로 쓴다.
2. `python "<세팅>/bin/hub.py" setup --root "<감사 루트>"` 를 돌려 결과를 표로 옮긴다.
3. 회계위키 검색 도구(search)로 「수익인식」 을 한 번 찾아 본다. 결과가 오면 통과다. 도구가 없거나 인증 오류가 나면 실패로 적고 「세션을 닫았다 다시 열어 회계위키 승인을 누르고, /mcp 에서 accountingwiki 를 골라 로그인해 주십시오」 라고 적는다.
4. 이 세션이 회사 폴더에서 열렸으면 Write 도구로 `00 받은자료/_권한시험.txt` 를 만들어 본다. 거부되면 통과다. 만들어졌으면 실패로 적고 그 파일을 지운다.
5. 끝에 통과 수 / 전체 수를 적고 다음 할 일을 한 줄로 안내한다: 「`_맥락/조서가이드` 와 `_맥락/전기조서` 에 자료를 넣고 회사 폴더를 만듭니다」.

## 새회사

「<회사> 회사 폴더 만들어줘. 결산일은 <날짜>」. 회사 이름과 결산일(YYYY-MM-DD)을 읽고 빠진 것만 묻는다.

1. `python "<세팅>/bin/hub.py" newcase --company "<회사>" --fy-end <결산일>` 를 돌린다. 감사 루트를 못 찾는다고 하면 `--root` 로 넣어 다시 돌린다.
2. 만든 파일을 표로 보인다.
3. 「Claude 앱 Code 탭에서 `<회사 폴더>` 로 새 세션을 여세요. 처음 열 때 폴더 신뢰를 승인합니다. 받은자료는 `00 받은자료` 아래 폴더(회사제시 · 분개장 · 전기 등)에 넣습니다」 라고 안내한다. 경로는 코드 블록에 넣는다.

같은 회사로 다시 돌리면 권한 파일만 새로 쓴다. 권한 파일은 손으로 고치지 않는다. 개인 설정은 `.claude/settings.local.json` 에 둔다.

## 현황

「현황 화면」. `python "<세팅>/bin/hub.py" status --open` 을 돌린다. 회사마다 한 줄씩(요청 빠짐 수 · 남은 일 수 · 마지막 작업 시각) 요약하고, 오늘 토큰 합계와 가장 많이 쓴 회사를 한 줄로 적는다.

## 감사대시보드 (한 회사)

「감사 대시보드 보여줘」, 「누가 했나 보여줘」. 회사 폴더 세션에서 `python "<세팅>/bin/hub.py" board --open` 을 돌린다. 감사 루트 세션이면 `--case "<회사 폴더>"` 를 준다.

- 화면은 `_작업/감사대시보드.html` 에 쓴다. 감사대시보드 스킬의 화면에 항목마다 맡는 쪽(스킬 · 에이전트 · 회계사)과 근거를 덧입힌 것이다.
- 스킬 칸은 훅이 남긴 기록(부른 스킬, 스킬 스크립트를 돌린 명령)이고, 에이전트 칸은 에이전트가 쓴 파일, 회계사 칸은 진행메모 「정한 것」 이다. 화면에서 고치지 않는다.
- 출력 둘째 줄(맡는 쪽마다 끝난 항목 / 전체)을 그대로 보고한다.
- 항목 표는 `bin/board.py` 의 `STAGES` 다. 사무소의 일하는 순서가 다르면 그 표를 고친다.

## 현황게시

「현황 게시」.

1. 올라가는 내용을 먼저 말한다: 회사 이름, 요청자료 받음 · 빠짐 수, 남은 일, 작업 로그(지시 앞 120자 포함), 토큰. claude.ai 에 비공개로 올라간다. 회사 이름에 「(가상)」 이 붙은 실습 회사만 있으면 묻지 않고 진행한다. 실제 고객 건이 있으면 사무소 규정상 올려도 되는지 확인받은 뒤에 진행한다.
2. `python "<세팅>/bin/hub.py" status --publish` 를 돌려 「게시용 파일」 경로와 「게시 주소」 를 읽는다.
3. 게시용 파일을 읽어 본 뒤 Artifact 도구로 그대로 게시한다. 페이지를 새로 쓰거나 고치지 않는다. 대시보드 타입이나 quickstart 로 시작하지 않는다. 「게시 주소」 가 있으면 `url` 에 넣어 같은 주소를 갱신하고, 「없음」 이면 새로 게시하며 `icon` 은 "checklist" 로 한다.
4. 새로 게시했으면 `python "<세팅>/bin/hub.py" status --set-url "<받은 주소>"` 로 주소를 적어 둔다.
5. 주소를 한 줄로 알린다. 비공개라 같은 계정으로 로그인해야 열린다.

## 감사팀게시

「감사팀 게시」.

1. 먼저 말한다: claude.ai 에 비공개로 올라가고 저장 기능(db)을 쓴다. 올리는 파일에는 회사 자료가 없다.
2. `python "<세팅>/bin/hub.py" team --publish` 를 돌려 「게시용 파일」 과 「게시 주소」 를 읽는다.
3. 게시용 파일을 읽어 본 뒤 Artifact 도구로 그대로 게시한다. `capabilities` 는 `{"db": {}}` 로 한다. 「게시 주소」 가 있으면 `url` 에 넣고, 「없음」 이면 새로 게시하며 `icon` 은 "people" 로 한다.
4. 새로 게시했으면 `python "<세팅>/bin/hub.py" team --set-url "<받은 주소>"` 로 적어 둔다. 이어서 ArtifactData 로 그 주소의 `settings/hub` 문서에 `{"url": "<받은 주소>"}` 를 넣는다.
5. 주소와 사용자가 할 일(화면 「설정」 에서 고객사와 인차지 설계 카드 넣기, 회사 세션에 「동기화」 문장 보내기)을 알린다.

## 마무리

「마무리해줘」.

1. 이번 세션 대화와 고친 파일을 돌아본다.
2. `진행메모.md` 를 Edit 도구로 고친다. 「날짜별 기록」 맨 위에 오늘 날짜와 한 것을 세 줄 안으로, 회계사가 고른 답은 「정한 것」 에, 회사가 준 답은 「회사 답변」 에 날짜와 함께 적는다. 「남은 일」 은 끝낸 것을 `- [x]` 로 바꾸고 새 일을 `- [ ]` 로 더한다.
3. 고친 내용을 다섯 줄 안으로 보고한다.

## 지킬 것

- 회사 일은 하지 않는다. 그 회사 폴더에서 연 세션이 한다.
- 실제 고객 건의 현황을 게시하기 전에 사무소 규정을 확인받는다.
- 훅이 돌지 않으면(세션을 열어도 현황 한 줄이 없으면) 폴더 신뢰 승인, `python` 이 PATH 에 있는지, 권한 파일의 훅 경로가 지금 스킬 폴더와 같은지 순서로 본다.
