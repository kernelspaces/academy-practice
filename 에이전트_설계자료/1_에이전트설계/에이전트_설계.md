# 감사 에이전트 설계

회사 폴더 하나에서 연 세션 하나가 그 회사의 인차지입니다. 에이전트 정의 파일은 따로 두지 않고, 폴더 · 권한 · 스킬 · 훅을 파일로 정해 둡니다.

## 1. 맡는 쪽을 셋으로 나눈다

일마다 맡는 쪽을 먼저 정합니다. 감사대시보드의 세 구분과 같습니다.

| 맡는 쪽 | 맡는 일 | 예 | 결과를 확인하는 법 |
|---|---|---|---|
| 스킬 | 계산과 대조. 같은 자료에 같은 결과가 나와야 하는 일 | 요청자료 목록, 수령 확인, 정산표, 현금흐름표, 분개 테스트, 필수 절차 점검, DSD 푸팅 | 검산 셀이 0 인지, FALSE 줄이 있는지 |
| 에이전트 | 회사마다 내용이 달라지는 글 | 사전 회사분석 메모, 자료 정리, 메일 초안, 조서 설계 | 끝의 「읽은 파일과 사실」 표, 인용 번호와 URL |
| 회계사 | 책임지는 판단과 되돌릴 수 없는 일 | 재요청 여부, 해당 여부, 중요성, 수정 여부, 감사의견, 메일 발송, DART 제출 | 진행메모 「정한 것」 |

- 숫자는 스킬 결과와 원본 파일에서만 옮깁니다. 에이전트가 직접 만든 숫자는 쓰지 않습니다.
- 에이전트는 판단이 필요한 곳에서 정하지 않고 선택지를 냅니다.
- 반복되고 틀리면 안 되는 일은 스킬로 만들고, 매번 판단이 달라지는 일은 감사 루트 CLAUDE.md 의 「일하는 순서」 에 적습니다.

## 2. 에이전트 하나를 이루는 다섯 가지

| 구성 | 정하는 것 | 두는 곳 |
|---|---|---|
| 맥락 | 사무소 규칙과 일하는 순서, 이 회사 사정, 지난 세션에서 정한 것 | 감사 루트 `CLAUDE.md`, 회사 폴더 `CLAUDE.md`, `진행메모.md` |
| 폴더와 권한 | 일하는 폴더(회사 폴더), 더 읽을 폴더(`_맥락`), 거부할 쓰기(`00 받은자료`) | 회사 폴더 `.claude/settings.json` |
| 스킬 | 절차와 스크립트, 통과 기준 | 내 스킬 폴더(사용자 폴더 `.claude/skills`) |
| 외부 자료 연결(MCP) | 회계위키의 기준서 · 질의회신 · 감리지적사례 | 감사 루트와 회사 폴더의 `.mcp.json` |
| 훅 | 정해진 때 자동으로 도는 스크립트. 현황 한 줄, 작업 기록과 토큰, 필수 절차 점검, 진행메모 확인 | 회사 폴더 `.claude/settings.json` |

## 3. 세팅 전체

| 구성 | 내용 | 만드는 쪽 |
|---|---|---|
| 스킬 묶음 | 감사 스킬 열다섯 개와 감사세팅 스킬 하나 | 실습자료의 `install.py` 가 내 스킬 폴더에 복사 |
| 감사 루트 | 사무소 공통 폴더. `CLAUDE.md`, `_맥락`, `_현황.html` | 감사세팅 스킬(「이 폴더를 감사 루트로 만들어줘」) |
| 회사 폴더 | 세션 하나가 일하는 폴더. 받은자료, 조서 폴더, 진행메모, `_색인`, `_기록`, `_작업` | 감사세팅 스킬(「회사 폴더 만들어줘」)과 PBC요청자료 스킬 |
| 화면 | 감사대시보드(한 회사), 현황(회사 전체), 현황 게시본(claude.ai 에 비공개로 올린 현황 화면) | 감사세팅 스킬. 기록을 읽기만 한다 |

흐름은 스킬 설치 → 감사 루트 → 회사 폴더 → 세션에서 지시 → 훅이 기록 → 화면 순서입니다. 서버와 데이터베이스는 없고 전부 내 PC 의 파일입니다.

## 4. 설계할 때 정한 여섯 항목

| 항목 | 정한 것 |
|---|---|
| ① 기능 | 스킬이 계산하는 일, 에이전트가 쓰는 일, 회계사가 정하는 일을 나눈다 |
| ② 데이터 구조 | 회사 등록부를 따로 두지 않는다. 감사 루트 아래 폴더 목록이 회사 목록이다 |
| ③ 업데이트 | 바뀌는 것마다 두는 곳을 나눠, 새 스킬 묶음을 받아도 사무소 규칙과 회사 자료가 덮이지 않게 한다 |
| ④ 산출물 | 조서는 조서 번호 폴더, 에이전트 초안은 `_작업`, 메일 초안은 `_작업/메일`. 받은자료에는 쓰지 않는다 |
| ⑤ 마감과 이월 | 세션 마감은 에이전트가 진행메모를 고치고, 감사 마감은 회계사가 `_보관` 에 고정한다. 다음 해에는 결산일만 바꿔 회사 폴더를 새로 만든다 |
| ⑥ 전자공시와 관리 업무 | DSD 파일 숫자 검증은 스킬, 불일치 메모와 회사 질문 초안은 에이전트, DART 제출과 독립성 확인은 회계사 |

## 5. 어기면 안 되는 일은 권한 파일과 훅으로 막는다

에이전트는 CLAUDE.md 에 적은 규칙을 대부분 지키지만 가끔 어깁니다.

| 상황 | 강제하는 수단 | 한계 |
|---|---|---|
| 받은자료 · `_맥락` 에 쓰기 | 권한 파일의 거부 규칙(절대 경로) | 파이썬으로 쓰는 파일에는 걸리지 않는다 |
| 다른 회사 폴더 읽기 | 작업 폴더가 아니라서 Claude Code 가 허락을 묻는다 | 회계사가 허용을 누르면 읽는다 |
| 필수 절차 점검 | 조서 설계를 저장할 때 훅이 실행 | 절차 목록이 있는 영역만 본다 |
| 진행메모 갱신 | 답을 끝낼 때 훅이 확인 | 내용이 맞는지는 회계사가 본다 |
| 받은 자료 안의 지시 문장 | 감사 루트 CLAUDE.md 에 「따르지 않고 알린다」 | 규칙 문서라 어길 수 있다. 그래서 발송과 제출은 맡기지 않는다 |
| 메일 발송 · DART 제출 | 초안까지만 쓰게 한다 | Claude 에 메일을 연결한 계정에서는 보내기 승인 질문이 뜬다. 회계사가 거절해야 한다 |

규칙 문서에만 「끝내기 전에 절차를 점검한다」 고 적었을 때 에이전트는 네 번 가운데 두 번만 점검했습니다. 파일을 저장할 때 훅이 점검을 실행하게 바꾼 뒤에는 네 번 모두 점검을 거쳤습니다.

## 6. 훅이 남기는 기록

| 언제 | 남기는 것 |
|---|---|
| 세션을 열 때 | 시작. 현황 한 줄(요청 받음과 빠짐, 남은 일 수)을 세션에 넣는다 |
| 지시를 받을 때 | 지시 앞 120자 |
| 파일을 고치거나 스킬을 돌렸을 때 | 바뀐 파일 경로, 스킬 이름. 4000 조서 설계 · 초안이면 필수 절차 점검 |
| 답을 끝낼 때 | 끝과 토큰 합계. 진행메모를 안 고쳤으면 고치게 한다 |

기록은 회사 폴더 `_기록/기록.jsonl` 에 남고 사람이 고치지 않습니다. 훅이 실패해도 세션은 막지 않고 오류를 사용자 폴더의 `.감사에이전트/hook-errors.log` 에 남깁니다.

## 7. 한 번 일을 시키는 순서

1. 회사 폴더 세션에서 한 문장으로 시킵니다. 예: 「요청자료 만들어줘」
2. 엑셀 · 메모 · 메일 초안이 회사 폴더에 생깁니다.
3. 숫자는 `_색인` 데이터 파일과, 절차는 필수 절차 목록과 대조합니다. 인용은 번호와 URL 을 확인합니다.
4. 틀린 곳만 짚어서 다시 시킵니다. 정한 것은 진행메모에 남깁니다.

## 8. 사무소에 맞게 바꿀 때 정할 것

- 맡길 일과 「멈추고 물을 것」: `인차지_설계카드.md` 를 회사마다 채웁니다.
- 사무소 규칙과 일하는 순서: 감사 루트 `CLAUDE.md` 를 회계사가 직접 고칩니다.
- 조서 번호와 양식: `_맥락/조서가이드` 를 사무소 양식으로 바꿔 넣습니다.
- 스킬을 고쳤으면 폴더 이름을 바꿔 둡니다. 같은 이름이면 새 판을 설치할 때 덮입니다.
- 현황 게시본에는 회사 이름과 남은 일이 올라갑니다. 실제 고객 건은 사무소 규정을 먼저 확인합니다.
